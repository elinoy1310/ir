## שלב 1 – טעינת מסמכי UK ו-US  

**מטרה:**  
לאחד את כל מסמכי הפרלמנטים (UK ו-US) למבנה נתונים אחד, הכולל:  
טקסט גולמי, תווית (UK=0, US=1), ושם קובץ — כדי להכין את הדאטה לשלב הווקטוריזציה והלמידה.

**ביצוע:**  
נוצרה תיקייה `exe2` הכוללת שתי תיקיות:

- `UK` – מסמכי פרלמנט בריטיים  
- `US` – מסמכי הקונגרס האמריקאי  

נכתב סקריפט `stage_0.py` המכיל את הפונקציה `load_corpus(base_dir)`, המבצעת את השלבים הבאים:

1. בניית נתיבים לתיקיות:  
   - `uk_dir = base_dir/UK`  
   - `us_dir = base_dir/US`  

2. יצירת שלוש רשימות ריקות:  
   - **texts** – רשימת טקסטים; כל איבר הוא תוכן של מסמך אחד (נאום/דיון).  
   - **labels** – רשימת תוויות מספריות;  
     - `0` עבור מסמך שמקורו בתיקיית `UK`  
     - `1` עבור מסמך שמקורו בתיקיית `US`  
   - **filenames** – רשימת שמות קבצים (ללא הנתיב המלא) לצורך מעקב ותיעוד.

3. מעבר על כל קובץ בתיקיית `UK`:  
   - פתיחת הקובץ עם קידוד `utf-8` והתעלמות משגיאות (`errors="ignore"`).  
   - קריאת תוכן הקובץ והוספתו לרשימת `texts`.  
   - הוספת הערך `0` לרשימת `labels` (מסמך UK).  
   - הוספת שם הקובץ (למשל `debates2023-06-28.txt`) לרשימת `filenames`.  

4. מעבר על כל קובץ בתיקיית `US`:  
   - פתיחת הקובץ וקריאת הטקסט לתוך `texts`.  
   - הוספת הערך `1` לרשימת `labels` (מסמך US).  
   - הוספת שם הקובץ ל־`filenames`.  

5. בסיום הפונקציה מוחזרת השלישייה:  
   `texts, labels, filenames`.

בקטע ה־`main` של הקוד בוצעו הצעדים הבאים:

- הגדרת הנתיב הבסיסי:

    base_dir = r"...נתיב...\exe2"

- טעינת הנתונים:

    texts, labels, filenames = load_corpus(base_dir)

- הדפסת מידע לבדיקה:

    Total documents: 689  
    UK/US labels: [0, 0, 0, 0, 0, ...]  
    Example filename: debates2023-06-28.txt  
    First document preview: We have a rule at the moment...

**תוצאות:**  
- נטענו **689 מסמכים** משתי התיקיות יחד (UK + US).  
- כל המסמכים מופיעים ברשימות באופן תקין:  
  - תחילה כל המסמכים מ־UK עם `label = 0`,  
  - לאחר מכן כל המסמכים מ־US עם `label = 1`.  
- שלושת הרשימות (`texts`, `labels`, `filenames`) באורך זהה (689), כך ש־i בכל אחת מהן מתייחס לאותו מסמך.  

שלב זה מייצר לנו נקודת פתיחה ברורה: יש לנו אוסף מסמכים אחיד משני הפרלמנטים, עם תיוג מקור ושיוך לשם קובץ, מוכנים להמשך העיבוד ובניית הייצוגים המספריים.

## שלב 2 – בניית ייצוג TF-IDF אחיד למסמכי UK+US  

**מטרה:**  
להמיר את רשימת המסמכים משלב 1 למטריצה מספרית, כך שכל מסמך יוצג כווקטור TF-IDF באותו מרחב מאפיינים.  
מטריצה זו תשמש אותנו בהמשך עבור:  
- אלגוריתמי Clustering (למשל KMeans, HDBSCAN)  
- מודלי Classification (כמו SVM, Logistic Regression וכו’)  
- רשתות נוירונים (ANN)  
- ויזואליזציות לדירוג ואשכול.

**ביצוע:**  

נכתב סקריפט (למשל `stage_1_vectorize.py`) שמגדיר פונקציה `build_tfidf_vectors(texts, max_features=5000)`. הפונקציה משתמשת במחלקה `TfidfVectorizer` מספריית `scikit-learn` כדי לבנות את הייצוג:

1. הגדרת ה־Vectorizer:

    from sklearn.feature_extraction.text import TfidfVectorizer

    vectorizer = TfidfVectorizer(
        max_features=5000,
        stop_words="english"
    )

הסברים על הפרמטרים:

| פרמטר                  | משמעות                                                                                 |
|------------------------|-----------------------------------------------------------------------------------------|
| `max_features=5000`    | מגביל את מספר המאפיינים ל־5,000 מונחים (מילים) החשובים ביותר בקורפוס הכולל           |
| `stop_words="english"` | מסיר מילים נפוצות באנגלית (stopwords) שלא מוסיפות משמעות מבחינת תוכן (the, and וכו’) |

2. התאמת ה־Vectorizer לטקסטים וחישוב מטריצת TF-IDF:

    X = vectorizer.fit_transform(texts)

- כל שורה במטריצה `X` מייצגת מסמך אחד מהקורפוס (UK או US).  
- כל עמודה מייצגת מונח (מילה) ש־TfidfVectorizer החליט לכלול במילון (עד 5000 מאפיינים).  
- כל ערך בתא הוא משקל TF-IDF של אותה מילה באותו מסמך.  
- המטריצה היא Sparse (דלילה), כלומר מאוחסנת בצורה חסכונית בזיכרון כיוון שרוב הערכים הם אפסים.

3. הפונקציה מחזירה:

    return X, vectorizer

כאשר:

- `X` – מטריצת TF-IDF בגודל `(מספר_מסמכים, מספר_מאפיינים)`.  
- `vectorizer` – האובייקט שמחזיק בתוכו את המודל וה־vocabulary (מיפוי בין אינדקס עמודה למונח הטקסטואלי).

בחלק ה־`main` של הקוד:

1. טעינת המסמכים מהשלב הקודם:

    texts, labels, filenames = load_corpus(base_dir)

2. בניית וקטורי TF-IDF:

    X_tfidf, tfidf_vectorizer = build_tfidf_vectors(texts)

3. הדפסת מידע לבדיקה:

    TF-IDF shape: (689, 5000)

וכן הצצה לווקטור הראשון בפורמט Sparse, לדוגמה:

    (0, 2795)  0.0505
    (0, 3017)  0.0528
    (0, 4077)  0.0719
    ...

המשמעות של שורות אלה:

- `(0, 2795)` – הערך בתא של מסמך מספר 0 (השורה הראשונה) עבור המונח בעל אינדקס 2795 במילון.  
- `0.0719` – ערך TF-IDF למונח מסוים באותו מסמך (ככל שהערך גבוה יותר, המונח נחשב חשוב יותר לאותו מסמך ביחס לקורפוס).

**תוצאות:**  

- התקבלה מטריצה:

    TF-IDF shape: (689, 5000)

  כלומר:
  - 689 שורות – מסמכים (מכלל מסמכי UK+US).  
  - 5000 עמודות – המונחים שנבחרו כמאפיינים הטקסטואליים.  

- מסמכי שני הפרלמנטים (UK ו-US) מיוצגים כעת באותו מרחב מאפיינים, מה שמאפשר להשוות ביניהם, לבצע clustering, לבצע סיווג ולבנות מודלים אחידים על שני המקורות.

**יתרונות השלב:**  

- ייצוג טקסטואלי סטנדרטי ונפוץ (TF-IDF), שמתאים במיוחד לאלגוריתמים קלאסיים של אחזור מידע ולמידת מכונה.  
- שימוש בספרייה קיימת (`scikit-learn`) בהתאם להנחיית המרצה – להיעזר בכלים מוכנים ולא לממש ידנית חישובי TF-IDF.  
- יצירת בסיס אחיד לכל שאר שלבי התרגיל (clustering, classification, ANN ועוד).
